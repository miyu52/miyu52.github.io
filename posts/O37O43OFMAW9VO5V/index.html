Dockerd 配置代理

发表于2025-03-04|更新于2025-03-04|DevOps
|总字数:805|阅读时长:3分钟

根据 Docker 官方文档 HTTP/HTTPS 代理配置指南，Docker 守护进程（dockerd）的代理需通过 Systemd 环境变量 配置，而非 daemon.json 文件。以下是详细步骤及注意事项：

配置原理

Docker 守护进程在启动时会读取 Systemd 管理的环境变量 HTTP_PROXY、HTTPS_PROXY 和 NO_PROXY。这些变量需通过 Systemd 服务文件覆盖 的方式设置，确保代理对所有 Docker 操作（如 docker pull、docker build）生效。

具体步骤

1. 创建 Systemd 服务覆盖目录

2. 创建代理配置文件

在 /etc/systemd/system/docker.service.d/http-proxy.conf 文件中添加以下内容（替换 [proxy-server] 和 [port] 为实际代理地址和端口）：

  • 代理认证：若需用户名密码，格式为 http://user:password@proxy-server:port（注意密码明文存储的风险）。
  • HTTPS 代理：若代理服务器支持 HTTPS，可替换为 https://...。
  • 排除地址：NO_PROXY 定义不通过代理访问的地址（如内网仓库或本地服务）。

注意事项

1. 代理类型兼容性

  • Docker 守护进程仅支持 HTTP/HTTPS 代理，不支持 SOCKS 协议。若需使用 SOCKS 代理，需通过工具（如 privoxy）将 SOCKS 转换为 HTTP 代理。

常见问题排查

1. 连接超时

  • 确认代理地址和端口正确。

  • 检查防火墙是否放行代理端口。

  • 使用 curl 测试代理连通性：

2. 证书错误

  • 若代理服务器使用 HTTPS 或自签名证书，需确保 Docker 信任代理的 CA 证书。

3. 配置未生效

  • 确保执行了 systemctl daemon-reload 和 systemctl restart docker。
  • 检查是否有其他配置文件覆盖了代理设置（如旧版 /etc/default/docker）。
